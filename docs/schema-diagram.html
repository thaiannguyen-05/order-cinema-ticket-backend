⚠ Refactor notes (faithful to schema, not hidden):
1. Seat.filmId: String @db.Uuid → FilmOfCinema.id — name suggests Film.film_id but points to join hub. Consider rename to filmOfCinemaId.
2. Payment.orderId: String @unique @db.Uuid — declared but has no @relation; real link is Order.paymentId: Int? → Payment.id (N Orders per Payment). Dangling column — decide 1-1 vs 1-N before refactor.
3. Triangle FKs: Seat→Cinema + Seat→FilmOfCinema→Cinema and Ticket→Seat + Ticket→FilmOfCinema + Seat→FilmOfCinema — denormalized, needs composite guard or removal.
4. FilmOfCinema @@unique([filmId, cinemaId]) with no datetime — one Film×Cinema pair only; cannot model two showtimes. If showtimes needed, add startsAt / room and extend unique.
5. Manual PKs: Cinema.cinema_id Int and Film.film_id Int have no @default(autoincrement()) — external ID import assumed.
6. Type mismatch: Film.film_id Int vs every other PK UUID — UserRecommendation.filmId Int is correct but inconsistent with UUID convention.

5. Reading paths for refactor

Catalog: Film ─≺ FilmOfCinema ≻─ Cinema, then FilmOfCinema ─≺ Seat ─1:1─ Ticket. Every Seat/Ticket hangs off the hub.
Ordering: User ─≺ Order 1:1 Ticket 1:1 Seat, Order ─≻ Payment (N:1). Deleting a User/Ticket with an Order is blocked (Restrict); deleting FilmOfCinema/Cinema/Seat cascades tickets away — dangerous, review before refactor.
Identity: User ─≺ Session (Cascade, 1 per IP), soft-delete via User.deletedAt? does not cascade.
Discovery: User ─≺ EventTracking (SetNull keeps analytics), User ≺ UserRecommendation ≻ Film (ranked N:M).
Infra: Outbox standalone transactional outbox pattern.
