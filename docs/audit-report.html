4. Deep-dive example: DDoS & abuse protection

You asked for DDoS as the worked example. Verdict: weak against L7 floods and credential-stuffing; money path is explicitly unthrottled.

ControlCurrentGap / exploit
Rate limitThrottlerModule [{ttl:60, limit:50}] (app.module.ts:36-41) + ThrottlerBehindProxyGuard tracking req.ip (proxy.ratelimit.guard.ts:6-13)In-memory store only (no ThrottlerStorageRedis) → per-instance buckets, trivially bypassed with N replicas or restarts. trustProxy:true (main.ts:122) without trusted-proxy allowlist → X-Forwarded-For spoofing.
Money path@SkipThrottle() ×5 in payment.controller.ts:42,52,127,143,157 (POST /payment, checkout, sync, webhook, GET :id)Attacker can flood order-create/checkout/webhook at line rate. Only browser returns are throttled (10/60s). Webhook has no IP allowlist + static-secret auth → cheap to spam; each hit takes a Redlock + DB tx.
Auth endpoints@Throttle 5/30s only on refresh-tokenlogin/register/forgot/verify (auth.controller.ts) have no throttle → brute-force, OTP-enumeration (generateCode Math.random, not crypto.randomInt), email-bomb via outbox.
Edge / networkFastify + fastifyHelmet with no options (main.ts:173); CORS without OPTIONS (main.ts:187); CSRF only in prod (main.ts:203-240)No CDN/WAF (Cloudflare/AWS Shield), no compose app service to put behind LB, DB/Redis/Rabbit ports exposed to host (docker.compose.yml:13,39-40,58), restart:no → container dies under pressure and stays down.
Costly workCheckout signs HMAC + Redlock 5-10s; webhook does tx + ticket updateNo proof-of-work, no captcha, no Idempotency-Key on POST /payment → double-click/retry amplifies DB + lock contention. expiresAt is client-controllable (create-payment.dto.ts:34-36) → attacker stretches holds.
DDoS hardening (ordered):
1. ThrottlerStorageRedis (ioredis) + per-route limits: auth 5-10/min, payment-create 20/min/user, webhook 60/min/IP + global 50/60s kept.
2. Remove SkipThrottle from money path; add @Throttle + ownership check already exists. Webhook: HMAC body + replay-id store + SePay IP allowlist.
3. trustProxy: restrict to LB CIDRs; helmet with CSP/HSTS; fix CORS OPTIONS; exclude webhook from CSRF (currently prod CSRF would 403 SePay).
4. Edge: Cloudflare / ALB + WAF, auto-scale app (add app service, restart:unless-stopped), close DB ports, SYN/backlog tuning.
5. Abuse: crypto.randomInt OTP, argon2id tuning + pepper, captcha on register/forgot, Idempotency-Key 24h on POST /payment.
6. Observe: http_server_duration histogram + 429/5xx counters + alerts; k6 stress + contention suites in CI.
